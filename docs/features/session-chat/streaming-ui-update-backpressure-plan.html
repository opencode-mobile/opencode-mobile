Streaming UI update backpressure

Make Session Chat timeline UI updates consistent and less laggy under dense streaming, large messages, and user scroll. Domain coalescing already works; this plan targets host geometry and scroll coupling to every content growth — not TextMate on the UI thread.

Acceptance gates

Manual device checklist — open until scenarios 1–6 are run.

Armed stream

Manual No multi-frame hitch per token batch while pinned.
Manual Works for small and ≥8k plain streaming paths.

Unarmed / drag

Manual Mid-history scroll does not jump while stream continues.
Manual Drag / fling: finger wins; brief stale text until settle OK.

Required + decorate

Manual Post-send required apply never sticks or drops.
Manual Final markdown: at most one intentional height jump.

Optional flags

Planning names only — never shipped as runtime toggles. Behavior landed directly in Phases 1–3 (animateSizeChanges = false, content/layout split, MessageListTimelineApplyHold, SessionChatMarkdownPaint).

What not to do

  • Chase TextMate / main-thread parse as the primary stream+scroll fix.
  • Absorb Sync / Pipeline into SessionMessageEngine to “fix jank.”
  • Reintroduce history-wide layoutSignature / list-wide Equatable discovery.
  • Animate row height during streaming on either platform.
  • Push scroll pin state into SessionChatUiState / ViewModel.
  • Micro-tune only the 16 / 48 ms cadence without the content / layout split.
