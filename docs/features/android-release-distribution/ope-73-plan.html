OPE-73 — Firebase App Distribution On Every Merge

Every successful merge to main produces one AAB and distributes it to the private android-internal tester group without publishing another Play testing-track release.

TriggerEvery push to protected main
ArtifactSigned Android App Bundle
AudiencePrivate android-internal group
StatusOwner setup pending

Delivery flow

1. MergeExact commit lands on main
2. BuildProtected CI signs and verifies the AAB
3. DistributeFirebase uploads through Play internal app sharing
4. InstallPrivate tester receives the Play-generated build

Checkpoints

CheckpointRequired resultStatus
Owner setup Link Firebase to Play; create the private group, dedicated App Distribution service account, JSON key, and protected GitHub secret. Pending approval
Agent implementation Add the main-push workflow, signing and signature verification, AAB upload, release notes, summaries, serialization, and cleanup. Implemented
Acceptance One merged build reaches Firebase, targets the private group, and installs through the tester flow without a Play-track release. Not started

Boundaries and risks

TopicContract
SigningUpload-key-signed AAB; internal app sharing generates APKs with a separate test certificate. The first Firebase install requires uninstalling the Play-internal build.
VersioningApp Distribution reserves 1000000000 + run_number for monotonic updates inside its separate tester channel.
CredentialsDedicated Firebase App Distribution Admin identity in the protected environment; PRs receive no credentials.
Run orderingSerialize without cancellation so a later merge cannot suppress an earlier distribution.
FailureA failed distribution fails the workflow but does not revert the merge.
ExcludedNo public invite, runtime SDK, in-app alert, feedback UI, extra Play-track release, Test Lab trigger, or iOS work.
