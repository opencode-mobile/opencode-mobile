Android Release Distribution

High-level plan for Firebase Test Lab + Google Play internal track. iOS App Store / TestFlight stays a no-op until an Apple Developer account exists. Source of truth: plan.md.

Phases

  1. OPE-70 — Human setup Personal ownership, one Cloud/Firebase project, Play draft, local upload key, separate service accounts, protected secrets.
  2. OPE-70 — Agent implementation Protected main-only Android Release workflow, signed and verified AAB/APK, CI version code, human semantic version name.
  3. OPE-70 — Human enrollment First manual AAB upload, Google-generated Play App Signing keys, publisher access, release left unpublished.
  4. OPE-71 — Distribution Extend the release workflow for one-tester Play internal; run independent bounded Test Lab Robo.
  5. OPE-72 — Observability Release/internal Crashlytics plus deliberately minimal Analytics; debug clean; no FCM or Remote Config.
OPE-70 is complete: CI-only Gradle signing and the protected manual Android Release workflow passed twice from main, and Play App Signing is active with the internal release left as a draft. PR Checks stay as-is; Test Lab is not a merge gate in this slice.
