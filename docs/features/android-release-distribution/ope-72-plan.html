OPE-72 — Release Observability

Add release-only Crashlytics and deliberately minimal Analytics, keep debug Firebase-free, and prove one protected, content-free non-fatal from a Play-internal build.

RuntimeRelease only
AnalyticsLifecycle and technical breadcrumbs only
VerificationOne non-fatal per version
StatusComplete

Implementation flow

1. ConfigureRegistered Firebase app and release dependencies
2. ProtectDebug no-op and minimal-Analytics manifest settings
3. PublishOptional protected workflow input, disabled by default
4. VerifyPlay install, two launches, Firebase dashboards

Checkpoints

CheckpointRequired resultStatus
Firebase setup Package dev.opencode.mobile, dedicated Analytics account, valid public client configuration, no private key. Complete
Implementation Release-only Crashlytics/Analytics, debug no-op, privacy metadata, protected one-shot verification, runbook. Complete
Automated boundary Debug excludes Firebase; release includes only intended products; manifests and focused builds pass. Complete
Protected-main acceptance Version 5 reported the controlled non-fatal, Analytics showed no custom events or screen views, and replacement version 6 launched without the version-5 startup crash. Complete

Collection boundary

AreaContract
AllowedAutomatic fatal, ANR, recorded non-fatal, and remaining automatic lifecycle/technical breadcrumb events in release builds.
DisabledAutomatic screen reporting, Advertising ID collection, ad personalization, app-assigned user IDs, and app-defined user properties.
RemovedAdvertising ID, Privacy Sandbox ad identifier, and Play install-referrer permissions.
Forbidden contentNo prompts, messages, paths, server URLs, credentials, custom events, timestamps, or unique values in verification data.
Excluded productsNo FCM, Remote Config, Performance Monitoring, App Distribution, Crashlytics NDK, or iOS observability.

Acceptance sequence

StepEvidence
Protected releaseRun Android Release from main with verify_crashlytics=true.
Play deliveryExpected signed AAB reaches internal testing and installs on the physical device.
CrashlyticsLaunch once to record, relaunch to upload, and confirm the expected version/device; a third launch does not repeat.
AnalyticsNo custom events, screen views, app-assigned identity/properties, Advertising ID collection, or personalized-ad signal.
Default safetyA normal release with verify_crashlytics=false keeps the verification path disabled.
