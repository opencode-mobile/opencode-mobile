Target architecture

Session Chat keeps one repository interface. Recovery, reduction, coalescing, decoration, caching, and invalidation become implementation details of a deep engine; the presentation layer receives exact changes instead of rediscovering them by scanning the timeline.

Fast text lane

  • Correctness-critical and frame-bounded.
  • Publishes current plain source without waiting for Markdown.
  • Prioritizes finalization and explicit operations.
  • Never performs history-wide work for one part delta.

Decoration lane

  • Optional, bounded, and safe to discard.
  • Keyed by session, block ID, content revision, and environment.
  • Runs off the UI executor and parses only changed blocks.
  • Failure leaves current plain text visible.

Closed-loop recovery

  • Healthy → recovering → healthy only after authority validates.
  • Failure, racing events, and repeated overflow keep recovery open.
  • The last good frame remains visible.
  • Connection epochs reject late work.

Provisional performance gates

Phase 1 locks the reference fixtures/devices and may tune numeric values. Boundedness, text independence, no UI-thread parsing, and no per-delta history scan are non-negotiable.

ConcernProvisional gate
Dense streaming latency SSE receipt → visible plain text p95 ≤ 50 ms on the reference trace.
UI executor work Frame apply p95 ≤ 4 ms; no parsing, highlighting, full projection, or event routing.
Publication cadence At most one text frame per display interval; continuously changing streams publish at least every 50 ms.
Delta complexity Work is proportional to the changed message/part and visible apply set, not total history.
Decoration safety Zero stale commits; failure leaves current plain text visible.
Memory/backpressure Every queue/cache exposes a high-water mark plus count and estimated-cost limits.
Scroll stability Unarmed anchor ID + offset preserved within native rounding; armed state settles at exact end.

Acceptance gate

Reliability

  • Recovery stays open after failed/raced reload.
  • Old session/connection work cannot publish.
  • Sibling parts and stable identities survive REST + SSE.
  • No-op mutations do not revise or republish.
  • All work queues and caches are bounded.

Responsiveness

  • Plain text is independent of Markdown.
  • No history-wide delta path remains.
  • Hot work stays off the UI executor.
  • Streaming and first-usable-history budgets pass.
  • Stale decoration never commits.

Rendering + scroll

  • Rows and blocks have stable identities.
  • Interleaved text blocks support Markdown.
  • Hosts apply declared row changes only.
  • Unarmed anchors survive append/restyle.
  • User gestures outrank optional enrichment.

Architecture + parity

  • Repository remains the small external seam.
  • One deep engine replaces old orchestration.
  • Engine/projector interfaces are test surfaces.
  • Shared fixtures verify observable parity.
  • Any product divergence is documented.

Dual lanes introduce height jumps Publish explicit layout changes and execute a single native scroll transaction.

Shared fixtures force identical native mechanics Share inputs and observable outcomes only, not implementation details.
Native memory exceeds character estimates Combine count/cost limits with high-water measurement and memory-pressure eviction.
