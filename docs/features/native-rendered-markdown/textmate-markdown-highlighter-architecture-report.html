TextMate Markdown Highlighter

opencode-mobile runs Shiki-derived TextMate grammars through a custom Kotlin Multiplatform interpreter. It emits scope stacks, compresses them into 18 product-owned semantic roles, and paints those roles with native Compose and SwiftUI theme tokens. This report also traces task ownership, generation-gated publication, cache lifetime, memory pressure, native regex allocations, and transient allocation hotspots.

Line-state model

1 · Resume Start a physical line with open begin/end or while rules from the previous line.
→
2 · Compete Find the earliest child rule and active end match. Grammar order and applyEndPatternLast resolve ties.
→
3 · Carry Close matched rules, or return unresolved dynamic end/while state for the next line with absolute token offsets.

This mirrors TextMate's line-oriented model and vscode-textmate's returned rule stack, but the mobile state is used only inside one complete fence parse.

Platform seam

Android · Joni

  • Joni 2.2.7 with UTF-8 and Ruby syntax
  • Concurrent compiled-regex cache
  • Grammar resources loaded from Android assets
  • Highlighter access serialized by MessageContentPreparer
  • Typed KMP render tree consumed directly by Compose

iOS · libonig

  • Oniguruma 6.9.9 static archives through C interop
  • Thread-local compiled-regex cache
  • Grammar resources copied into the application bundle
  • KMP render tree crosses a JSON bridge
  • UTF-16 spans paint through SwiftUI or off-main UIKit construction

Allocation pressure inside a fence

1 · Slice Build line, next-line, and boundary strings while carrying TextMate state.
→
2 · Re-index repeatedly Every regex search recreates UTF-8 bytes and two UTF-8/UTF-16 index arrays.
→
3 · Project and paint Allocate scope tokens, repaired span lists, JSON bridge data on iOS, and attributed output.

Phase 1 lifetime safety

iOS now accounts for successful libonig allocation/free operations, immediately releases successful alternation-decomposition probes, and exposes explicit cache cleanup. The accepted 30-minute simulated matrix completed 457 Android/Joni cycles and 1,128 iOS/libonig cycles with stable post-warm-up retained state and allocation/free equality. Phase 1 is closed; weighted retained-cache ownership remains part of the proposed single-owner engine.

Concurrency risk

The iOS regex map is thread-local, but the process-wide grammar bundle and tokenizer rule map remain shared mutable state reachable from detached preparation tasks.

Correctness boundary

Proven

  • Top-10 *-basic semantic fixtures on Joni and libonig
  • Manifest/resource consistency and alias resolution
  • Core rule shapes, line state, captures, includes, while, and injections
  • UTF-8 to UTF-16 offsets and non-overlapping final spans
  • Focused regression samples and native painting contracts

Still bounded

  • Broad generated Shiki corpus remains ignored
  • Bundle breadth does not equal exact tokenizer parity
  • TextMate remains disabled by default
  • No tokenizer time budget, cancellation, or cross-revision incrementality
  • Full Shiki theme/scope fidelity is outside the current render contract
