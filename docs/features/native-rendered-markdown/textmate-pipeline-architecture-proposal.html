External boundary

interface TextMateHighlightingEngine {
  suspend fun highlight(
    request: HighlightRequest
  ): HighlightResult

  suspend fun trim(
    level: MemoryPressure
  )
}

Input

Opaque fence key, caller-owned monotonic revision, language, exact source, priority intent, and policy epoch.

Output

Same identity, canonical language, semantic spans, diagnostics, and an all-or-nothing upgrade outcome. Timing stays internal.

Not exposed

Grammar objects, rule stacks, regex handles, native pointers, cache keys, queues, or worker mechanics.

Internal components

Request scheduler

Prioritizes, coalesces, applies deadlines, and drops background work first.

Grammar registry

Compiles bundled JSON into immutable, versioned grammar and rule programs.

Incremental tokenizer

Reuses compatible incoming line state and retokenizes only changed regions.

Regex runtime

Searches prepared UTF-8 line buffers through Joni or owned libonig adapters.

Role projector

Maps scopes to shared semantic roles through versioned repair behavior.

Cache coordinator

Applies weighted limits and safely trims grammar, regex, rule, and line state.

Metrics sink

Separates queue, compile, tokenize, repair, fallback, cancellation, and memory cost.

Engine owner

Serializes all mutable state, eviction, and native disposal on each platform.

One owner is a latency and memory choice, not merely a locking choice. A second isolated shard requires device evidence.

Request lifecycle

1Prepare a complete plain/fallback Markdown document.
2Publish usable source without waiting for TextMate.
3Queue each block with identity, revision, and intent.
4Execute on the single owner within time, search, and memory budgets.
5Validate generation and identity; attach decoration or discard.

How it becomes fast

Remove repeated work

  1. compile grammar programs and regexes once;
  2. prepare UTF-8 bytes and offset maps once per line;
  3. reuse the unchanged line-state prefix;
  4. reuse a suffix only after text and incoming state converge.

Protect interactive latency

  1. plain source bypasses the TextMate queue;
  2. final visible code preempts history;
  3. obsolete block revisions coalesce;
  4. background work stops first under device pressure.

Reliability invariants

  1. Complete source is always renderable.
  2. Highlighting changes decoration only.
  3. Only exact current identity and generation may publish.
  4. Superseded work cannot become the current cache entry.
  5. Cancellation is not a correctness mechanism.
  6. Limits return no upgrade, never corrupt spans.
  7. Final spans are deterministic and non-overlapping.
  8. Eviction changes performance only.
  9. Native regexes cannot be freed while leased or remain ownerless.
  10. Both platforms share quality and fallback classifications.
  11. Metrics contain no source or session/block identity.
