Tool State Machine

4 states

Each ToolPart cycles through a deterministic lifecycle. Every EventMessagePartUpdated for a tool replaces the full state — not a delta.

pending → running → completed or error
◌ Pending
status: "pending"

◉ Running

✓ Completed

Rendering Parts

type switch

Parts are not concatenated into a single text blob. Each part is a distinct visual component rendered in order. The renderer switches on type:

part.typeRender asStreaming behavior
text Chat bubble with markdown rendering delta — append to .text char by char
reasoning Collapsible “thought” section (hidden by default) Entire part arrives at once
tool Status card: spinner → result/error, icon per tool name Full state replacement on each event
step-start Invisible boundary (or episode divider) Entire part arrives at once
step-finish Token & cost footer Entire part arrives at once
file Rendered image / attachment thumbnail Entire part arrives at once
agent Subagent delegation badge Entire part arrives at once
subtask Subagent task block Entire part arrives at once
snapshot System metadata — typically hidden or compact Entire part arrives at once
patch
compaction
retry

Rendering loop

Pseudocode for the client-side render loop. Each part is independently rendered.

for each msg in messages:
  render(MessageHeader(msg.info))

  for each part in msg.parts:
    switch part.type:
      "text" → TextBubble(part.text, streaming: delta)
      "reasoning" → CollapsibleThought(part.text)
      "tool" → ToolCard(part.tool, part.state)
      "file" → FileAttachment(part.url, part.mime)
      "step-start" → EpisodeDivider()
      "step-finish" → TokenFooter(part.tokens)
      "agent" → AgentBadge(part.name)
      "subtask" → SubtaskBlock(part.description)
      default → // snapshot, patch, compaction, retry — hidden or compact

Streaming & state replacement

EventMessagePartUpdated carries either:

delta
delta: string
Append to an existing text part. Character-by-character streaming of response text.
replace
part: ToolPart // full state
Full state replacement for ToolPart. The state object transitions pending → running → completed|error. Replace the entire part in-place in your local array.
new
part: Part // no delta
A new part appeared — e.g. a reasoning or step-finish lands. Append it to the message's parts array.

Typical part progression

How a single assistant response unfolds on the wire:

step-start → reasoning → tool (pending) → tool (running) → text (delta…) → tool (completed) → step-finish
Each arrow corresponds to an EventMessagePartUpdated SSE event. The client appends/replaces parts in order as they arrive.
